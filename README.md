# Smart Key Box 3

เว็บจัดการช่องกุญแจด้วย Express และ SQLite (`sql.js`) โดยไม่ต้องคอมไพล์ native code บน Windows และยังคงหน้าตาเดิมเป็นหลัก

## ฟังก์ชัน
- เข้าสู่ระบบผู้ดูแลจากค่าที่ตั้งใน `.env` และเข้าสู่ระบบผู้ใช้จากบัญชีที่ผู้ดูแลสร้างให้
- ผู้ใช้ทั่วไปไม่มีสิทธิ์จัดการผู้ใช้หรือเปลี่ยนการตั้งค่าระบบ; เฉพาะผู้ดูแลเท่านั้นที่เพิ่ม/แก้ไข/ปิดบัญชีได้
- รหัสผ่านบัญชีผู้ใช้จัดเก็บเป็น hash ด้วย scrypt ไม่ได้เก็บเป็นข้อความธรรมดา
- เพิ่มช่องกุญแจและแก้ไขชื่อกุญแจ
- ยืม/คืนกุญแจ พร้อมวันเวลาและหมายเหตุในประวัติ
- เพิ่ม/แก้ไขชื่อ เบอร์โทร ชื่อเข้าสู่ระบบ รหัสผ่าน และเปิด/ปิดบัญชีผู้ใช้
- ค้นหาประวัติและกรองตามกิจกรรม พร้อมส่งออก CSV สำหรับเปิดใน Excel
- ปรับชื่อตู้ สถานที่ สีหลัก และสีเมนู โดยเก็บการตั้งค่าใน SQLite
- SQLite บันทึกลง `data/smartkeybox.db` (หรือ path ที่กำหนดใน `DATA_DIR`)

> ผู้ใช้เดิมที่มีในตัวอย่างยังไม่สามารถเข้าสู่ระบบจนกว่าผู้ดูแลจะตั้งชื่อเข้าสู่ระบบและรหัสผ่านให้จากหน้า “จัดการผู้ใช้” หรือเพิ่มผู้ใช้ใหม่ บัญชีผู้ดูแลใช้ `ADMIN_USERNAME` และ `ADMIN_PASSWORD` ใน `.env`

## ติดตั้งบน Windows
1. ติดตั้ง Node.js LTS จาก https://nodejs.org/ (Windows Installer `.msi`, ไม่ต้องใช้ Docker)
2. แตก ZIP แล้วเปิด PowerShell ภายในโฟลเดอร์ `SmartKeyBox3` ซึ่งมี `package.json`
3. ติดตั้ง dependencies:
   ```powershell
   npm.cmd install
   ```
4. สร้างไฟล์ `.env` จากตัวอย่าง:
   ```powershell
   Copy-Item .env.example .env
   ```
5. เปิด `.env` ด้วย Notepad แล้วแก้ `ADMIN_PASSWORD` ให้เป็นรหัสผ่านคาดเดายากอย่างน้อย 12 ตัวอักษร และ `SESSION_SECRET` ให้เป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร ห้ามแชร์ไฟล์ `.env`
6. เริ่มระบบ:
   ```powershell
   npm.cmd start
   ```
7. เปิด http://localhost:3000 แล้วเข้าสู่ระบบด้วย `ADMIN_USERNAME` และ `ADMIN_PASSWORD` ที่ตั้งใน `.env`

ถ้าหน้าต่าง PowerShell อยู่ผิดโฟลเดอร์ ให้ใช้ `cd` ไปยังโฟลเดอร์ที่มี `package.json` ก่อนรันคำสั่ง ตัวอย่าง:
```powershell
cd "$HOME\Downloads\SmartKeyBox3\SmartKeyBox3"
```

## ทำให้เป็นเว็บไซต์ออนไลน์ที่มี URL
การรันในเครื่องจะได้ URL เฉพาะเครื่อง (`localhost`) เท่านั้น การเผยแพร่ให้คนอื่นเข้าผ่านอินเทอร์เน็ตต้องนำโปรเจกต์ไป deploy บนโฮสต์ Node.js เช่น Render หรือ Railway

1. สร้าง Git repository ส่วนตัว แล้วอัปโหลดโค้ด โดยไม่อัปโหลด `.env`, `node_modules` หรือ `data/smartkeybox.db`
2. สร้าง Web Service จาก repository บนผู้ให้บริการโฮสต์
3. ตั้ง Build command เป็น `npm install` และ Start command เป็น `npm start`
4. ตั้ง environment variables: `NODE_ENV=production`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `DATA_DIR`
5. ผูก persistent disk/volume กับบริการ แล้วตั้ง `DATA_DIR` เป็น path ของ volume ตามที่ผู้ให้บริการกำหนด มิฉะนั้นข้อมูล SQLite อาจหายเมื่อ deploy หรือ restart
6. Deploy แล้วใช้ URL ที่โฮสต์สร้างให้ ทดสอบเข้าสู่ระบบ เพิ่มช่อง ยืม คืน ประวัติ และรีสตาร์ตตรวจสอบข้อมูล

ผมไม่สามารถสร้าง URL สาธารณะให้โดยตรงจากไฟล์นี้ได้ เพราะต้องมีบัญชีโฮสต์และต้อง deploy โปรเจกต์ในบัญชีของคุณก่อน

## ข้อควรทราบ
- ฐานข้อมูล SQLite เป็นไฟล์เดียว จึงต้องมี persistent disk/volume บนโฮสต์ออนไลน์ และควรสำรองข้อมูลเป็นประจำ
- โปรเจกต์นี้เป็นระบบต้นแบบสำหรับการศึกษา; ก่อนใช้กับกุญแจจริงในองค์กร ควรเพิ่ม rate limiting, ระบบสำรองข้อมูล และทดสอบความปลอดภัย
- การเปลี่ยนสีและชื่อเว็บบันทึกในฐานข้อมูลและจะแสดงกับผู้ใช้ที่เข้ามาในระบบเดียวกัน


## หน้าดูสถานะสำหรับผู้ใช้ทั่วไป (อ่านอย่างเดียว)
- เปิด `http://localhost:3000/status` เพื่อดูชื่อช่องและสถานะว่าง/ถูกยืม โดยไม่ต้องเข้าสู่ระบบ
- หน้านี้ไม่แสดงชื่อผู้ยืม ประวัติการใช้งาน หรือปุ่มทำรายการ และรีเฟรชอัตโนมัติทุก 10 วินาที
- API สาธารณะมีเฉพาะ `GET /api/public/status` ซึ่งส่งคืน `id`, `name`, `status` เท่านั้น
- URL นี้จะเปิดจากอุปกรณ์อื่นได้เมื่อเซิร์ฟเวอร์เข้าถึงได้ผ่านเครือข่ายหรือเผยแพร่ขึ้นโฮสต์แล้ว
